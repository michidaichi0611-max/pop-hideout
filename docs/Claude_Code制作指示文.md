# Claude Codeへの制作指示

以下の設定画集・仕様書と同梱の画像を、ゲーム制作の基準資料として使ってください。

## あなたの役割

あなたは制作統括として、一般的なゲーム開発スタジオのように専門部署を分けて考え、作業を進めてください。実在する会社の社名・作品・キャラクター・独自表現を模倣せず、役割分担と品質管理の考え方だけを参考にします。

### 仮想の制作部署

1. **制作統括・ディレクター**：目的、優先順位、仕様変更、完成条件を管理。矛盾や未決事項を記録する。
2. **ゲームデザイン部**：操作感、時間制、標的の出現、得点・時間ボーナス、難易度曲線を設計する。
3. **アート部**：添付資料に沿ってキャラクター、フィールド、UI、色、読みやすさを統一する。
4. **プログラム部**：入力、照準、命中判定、時間、エリア遷移、スコア、データ保存を実装する。
5. **アニメーション・VFX・サウンド部**：出現・隠れる・走る・被弾、発射・着弾・足音を軽く実装する。
6. **QA・パフォーマンス部**：操作、当たり判定、画面比率、負荷、エラー、既存機能への影響を確認する。

各部署は、作業前に受け取った仕様と依存関係を確認し、実装後は変更内容、確認方法、未解決点を制作統括へ返してください。制作統括は重複実装や仕様の食い違いを整理し、最終判断を一元化してください。

## 作業の進め方

1. **既存プロジェクトを調査**し、エンジン、使用言語、起動方法、現状の画面、未完了機能、テスト手段を確認する。プロジェクトの場所やエンジンを推測で置き換えない。
2. **既存データを保護**する。既存ファイルや大きなフォルダを削除・一括移動しない。破壊的変更が必要なら、先にバックアップまたは復元可能な変更方法を用意する。
3. 設定画集を参考に、まず**軽量な縦画面のプレイ可能な試作**を作る。高精細な3Dモデルの完成を待たず、2.5D・簡易モデル・スプライトで操作とゲームループを検証する。
4. 画面を押す、ドラッグする、指を離して撃つ、命中する、ボーナスで時間が増える、10〜20秒ごとに短くエリアが切り替わる、という縦切りの遊びを最後まで動かす。
5. 実行・テストし、エラーを修正する。変更したファイル、実行したコマンド、結果、残る制約を報告する。
6. **確認質問は作業の最後にまとめて提示**する。途中で質問して作業を止めない。妥当な可逆的仮定を置いて先へ進み、仮定は `ASSUMPTIONS.md` 等に記録する。進行を止めるほど重大な不明点があっても、まず安全で後から変更できる仮設定を使って、レビュー可能な試作まで仕上げる。

## ゲーム仕様

- 仮称：ポップ・ハイドアウト。縦画面、片手操作のカジュアルな標的シューティング。
- プレイヤーは画面手前に小さく見える背面視点。奥に広いフィールドがあり、敵が物陰から出たり隠れたりする。
- 画面のゲーム領域を押した位置から照準操作を始め、指を動かして狙う。指を離すと即座に発射し、命中は即時判定（ヒットスキャン）する。軽いタップならその位置を狙って発射する。
- 指先で照準が隠れないよう、照準マークを指先より少し上に表示する。HUD操作中は誤射しない。
- 制限時間内に標的を撃つ。連続命中、正確な射撃、ボス発見・撃破などで得点と時間ボーナスを得る。ボーナス値は後で調整できるデータにする。
- フィールドは3〜5種類を想定。最初の試作は3種類でよい。各エリアは10〜20秒ごとに切り替え、初期値は15秒として調整可能にする。
- ステージ移動は0.8〜1.0秒。プレイヤーが横に走り、カメラと景色も横移動する。短い「ザッ、ザッ」という足音を付ける。移動中はゲームタイマーと射撃判定を止める。
- ステージを進めても背景物や遮蔽物の数を増やさない。難易度は敵の人数、顔の出し方、隠れる時間、出現位置、移動・逃走の動きで上げる。
- 敵は通常3種類＋ボス1体。通常敵は隠れる・のぞく・移動する・走って逃げる。ボスは他の敵より見つけにくいが、不公平な完全ランダムにはしない。
- 武器はカウボーイ風の拳銃と水鉄砲。照準・命中ルールは共通で、演出を変える。
- 拳銃は小さな発射光・短い弾道・控えめな着弾。水鉄砲は短い水流・水滴・水しぶき。敵は軽く揺れる、へこむ、跳ねるなどの反応をする。血や強いグロ表現は使わない。
- キャラクターは色や輪郭で見分けやすくする。各キャラクターの固有スキルや課金は将来候補であり、初回試作に必須ではない。性能差や課金限定能力を勝利条件にしない。

## ビジュアルと軽量化

- 画風は添付画像に沿った、親しみやすい西部劇風の2.5D。少し立体的だが、写実的な3D制作は要求しない。
- 低ポリゴンまたは平面スプライト、単純な形、少ないテクスチャ、控えめな不透明ハイライトを使う。透明ゼリー材質、複数の動的ライト、重い影、過剰な粒子、常時の物理シミュレーションを避ける。
- 背景の光や影は可能なら絵に含め、動かす要素だけを分ける。見えない敵や遠景を不要に更新しない。
- 画像生成シートはデザイン参考であり、フレーム位置の揃った完成スプライトシートではない。必要な箇所だけ切り出すか、簡易図形で仮置きし、素材の整列が必要ならその作業を明記する。透明背景を前提にせず、実ファイルを確認する。

## 完成条件

- 起動してタイトルまたはゲーム画面からプレイを開始できる。
- 画面を押して照準移動、離して発射ができ、画面のUIを誤射しない。
- 敵が複数の隠れ方で出現し、弾が即時判定され、命中反応が見える。
- コンボ・精密射撃・ボスのいずれかで残り時間が加算される。
- 同じ密度の3つのフィールドを短い横移動で切り替えられる。移動中はタイマーが止まる。
- 拳銃と水鉄砲の演出を切り替えられる。
- 低負荷設定を優先し、対象PCで確認可能な方法を用意する。実機性能が未確定なら、負荷を抑えた仮設定と確認項目を提示する。
- 起動・操作・主要ゲームループをテストし、結果を記録する。

## 最後にまとめて聞くこと

作業を止めずに試作を仕上げた後、未決事項だけを重複なく短いリストで尋ねてください。少なくとも、(1)最終タイトル、(2)全体の初期制限時間、(3)実行先と画面サイズ、(4)3〜5種類のステージの最終数、(5)キャラクター固有スキルを初回版に入れるか、(6)仮画像をどこまで本素材に置き換えるか、を確認します。既に資料で確定している操作・短い遷移・敵主体の難易度調整は再質問しないでください。
